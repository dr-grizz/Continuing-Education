# ADR 0016: Recipient-bound QR and claim-code distribution

Accepted October 28, 2026 at the project owner's request.

The integrated credential domain distributes already-issued accomplishments as badge-only, certificate-only or combined packages. A combined package references a single badge and its frozen certificate, both bound to the same approved learner. Existing manual/CSV issuance already inserts both outputs atomically when a certificate template is selected; the UI now names this option explicitly. Adding a certificate to an existing earned badge uses the certificate workspace and never reissues that badge.

Claiming is a delivery acknowledgment and authenticated access route. It does not establish eligibility, enroll learners, award credentials, transfer them, change signed content or enable public sharing. This preserves ADR 0011's identity and authority boundaries. Staff distribution creation and revocation require current `badges:manage` authority and the existing same-origin broker. The redemption endpoint derives the badge learner ID from the authenticated portal session and private account link; it accepts only the claim code from the browser. The exact application-owned claim page is added to the mock/Canvas sign-in return allowlists; arbitrary origins and query-bearing destinations remain refused.

Migration `027_credential_claims` adds workspace-scoped claim and event tables. Claim recipient, source, package, certificate, origin, hash and creation/expiry fields are immutable; event history is append-only. A private persistent HMAC key derives 100-bit Crockford-style codes from workspace and random claim UUID; only SHA-256 code hashes enter PostgreSQL. The staff-only detail route reconstructs active codes and locally generates QR PNGs with the same fragment-based claim link. Code material is never sent in request URLs, audit descriptions or public lookup responses. The landing page removes the fragment from browser history and retains the pending code in tab-local session storage through sign-in, clearing it after success.

The workspace transaction lock serializes creation and redemption across API instances. Repeated creation reuses the active distribution for the same award and package; expiration or explicit revocation permits a replacement. The first authorized redemption records the learner/time, while retries return the same receipt without issuing anything. Wrong-recipient, expired, revoked, invalid and unavailable credentials share a generic error. Ten redemption attempts per learner over five minutes are persisted in the event ledger. Unlinked/inactive accounts and withdrawn or unverifiable source awards cannot claim; unavailable distributions never display a fresh QR. Code revocation does not revoke an earned accomplishment or recall already downloaded files.

The local fixture command creates two clearly fictional mock learners, two paired badge/certificate accomplishments and three package examples, preserving unrelated data and identity links. It is idempotent for sample identities and credential snapshots, refuses conflicts, and is disabled for hosted, production or Canvas learner modes. It makes no Canvas or email-provider calls, even if certificate email is configured. Claims can be refreshed by rerunning the fixture command after earlier ones are claimed or expired.

This is recipient-specific delivery, not an open claim campaign where any scanner becomes eligible. No always-running worker or additional service is introduced. The existing private issuer/account links remain authoritative, the deployment audience gate remains in force, and certification/accepted Open Badges proof mechanisms remain separate work.
