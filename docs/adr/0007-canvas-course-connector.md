# ADR 0007: Staff-authorized Canvas course reads

Accepted for local implementation, October 14, 2026, at the project owner's direction.

Use the existing Canvas staff OAuth client and callback for optional API course-read scopes. A staff member must have both the portal permission and Canvas permission to initiate a read. Keep identity-only mode as the default until the developer key and subaccount are configured. API grants are encrypted at rest, bound to the verified staff identity and configuration, and refreshed server-side. They are never issued to the browser. An explicitly selected staff member owns scheduled reads; portal logout leaves that authorization available, while loss of access or revocation stops scheduled work.

Implement the resource client directly in the TypeScript backend using native HTTP. Development skills are not deployed portal dependencies. No Python runtime or separate integration identity/application is required by this connector. Use “Canvas courses” and “Course manager” in current user-facing text; keep existing role/scope identifiers compatible with stored records and API clients.

This is a narrow opt-in exception to ADR 0001's simulated external adapters: reading real course metadata is allowed when configured. Enrollment, learner identity and grades remain separate work. The prototype's local-only guard stays in force. Discovery changes no Canvas objects and creates no portal offerings. Background reads use their own durable jobs and create private encrypted temporary previews outside the portal database. Previews expire after 30 minutes. Both manual and scheduled reads require an explicit row or selected-course sync action by the authorized owner. Selected courses merge into the shared saved inventory, preserving unselected and previously synced courses. Per-course sync/source timestamps and a saved revision guard prevent stale replacements. The private preview remains available until expiry for additional selections, and an Imported courses tab shows the saved inventory independently. Nested discovery validates account ancestry through the existing account-details scope. The portal owns offering publication independently; listed/unlisted visibility remains planned.

At the owner’s October 14 direction, explicit row/selected-course sync now creates an unpublished offering draft for each unmapped source course. Discovery and scheduled reads still create no offerings. Enforce one default mapping per installation URL and course ID in the database; retries reuse the mapping. A conflicting existing manual course link stops the batch for review. Preserve every staff-owned offering field on subsequent syncs and protect mapped course links from accidental changes. Imported drafts leave unknown sales fields unset, display readiness warnings and cannot publish or accept registration/payment until complete. Existing sync permissions remain sufficient to create drafts; offering edit/publication permissions are unchanged. Migration `018_canvas_offering_drafts` supports only never-published imported drafts with missing numeric/type fields; manual creation remains validated.

See [setup and operational behavior](../canvas-courses.md), [mapping plan](../canvas-mapping-plan.md) and [staff authentication](../canvas-staff-auth.md).

October 15 amendment: [ADR 0008](0008-request-driven-demo.md) defers scheduled reads and moves manual preview execution into staff API requests. Existing schedule configuration remains historical; no always-running worker is required for the demo. The permission, encryption, preview and import protections above remain.
